## 1. 작업 목적

Room BE가 임시 연동된 상태에서 다음 4가지를 처리했다.

1. **시드 데이터 불일치 해결** — 사용자 성장(레벨/칭호/진행도) 표시가 서로 다른 기준으로 계산되던 문제.
2. **해제(인식) 화면 전면 카메라 전환** — 셀프뷰로 인(印)을 맺을 수 있도록.
3. **해제 화면 디자인 개선** — "먹·인장" 디자인 토큰에 맞춘 시각 정리.
4. **로그인/회원가입 구현** — 스키마만 있고 양쪽 다 비어 있던 인증을 백엔드·프론트·세션까지 end-to-end로.

모든 변경은 빌드(`assembleDebug`)·린트(`lintDebug`) 통과를 확인했다.

## 2. 시드 데이터 불일치 해결

### 2.1 문제

기존 `users` 시드는 `exp=1340 / level=7 / "중급닌자"`였으나, 같은 코드의 성장 로직과 어긋났다.

- 레벨 임계값(100/300/700)·칭호 기준·진행바(`exp % 500`)가 **서로 다른 계산식**을 사용 → 같은 exp에 대해 레벨/칭호/진행률이 불일치.
- 시드 하드코딩 값도 그 어느 계산식과도 맞지 않음.

### 2.2 해결 — exp 단일 소스화

`RoomMappers`의 성장 로직을 **누적 경험치 경계표 하나에서 모두 파생**하도록 정리했다.

```java
// 레벨별 누적 경험치 경계. index i = (i+1)레벨 진입 누적 exp.
private static final int[] LEVEL_FLOORS = {0, 100, 300, 700, 1200, 1800, 2500};
private static final int LEVEL_STEP = 800; // 표 범위를 넘으면 이 간격으로 외삽
```

- `levelForExp(exp)` · `titleForExp(exp)` · `toProfile(...)` 의 진행도(`expIntoLevel`/`expForLevel`)를 **모두 이 표(= exp)에서 파생**.
- `toProfile`은 저장된 `current_level`/`title` 컬럼이 아니라 **exp를 단일 소스**로 사용 → 시드·마이그레이션으로 컬럼이 틀어져도 화면 표시는 항상 일관.

### 2.3 시드값 일관화

`NinjaDatabase` 시드 사용자를 성장표와 맞는 값으로 교체.

```text
exp=520 → 레벨 3 · 상급닌자 · 구간진행 220/400 (55%)
```

> 시드는 DB 최초 생성 시에만 적용되므로, 기존 설치본은 앱 데이터 삭제 시 새 값이 반영된다(삭제 안 해도 표시는 일관).

**변경 파일**: `data/mapper/RoomMappers.java`, `data/NinjaDatabase.java`

## 3. 해제(인식) 화면 전면 카메라 전환

### 3.1 변경

- `DismissActivity`에 `USE_FRONT_CAMERA = true` 상수 추가 → `CameraSelector.DEFAULT_FRONT_CAMERA` 사용.
- 전면 프리뷰는 좌우 반전되어 표시되므로 검출 박스도 맞춰 반전:
  `DetectionOverlayView.setMirror(true)` → `onDraw`에서 `[left,right] → [1-right, 1-left]` X 반전.

### 3.2 모델 입력은 미러하지 않음 (의도)

YOLOX 모델 입력은 **센서 원본 그대로**(미러 X)를 유지한다.

> 모델이 미러되지 않은 손모양으로 학습되었으므로, 인식 정확도 보존을 위해 **모델 입력을 뒤집지 않는다.** 표시용 박스만 반전한다.

**변경 파일**: `ui/dismiss/DismissActivity.java`, `ui/common/DetectionOverlayView.java`

## 4. 해제 화면 디자인 개선

기존 평면 스크림 위주 레이아웃을 "먹·인장" 토큰에 맞춰 정리했다.

| 요소 | 내용 | 리소스 |
|---|---|---|
| 상단 그라데이션 스크림 | 상태 칩/링 가독성 확보 | `bg_dismiss_scrim_top.xml` |
| 중앙 조준 가이드 | 손 위치 안내 둥근 프레임 + 안내 문구 | `bg_dismiss_reticle.xml` |
| 상태 칩 | 현재 인식/신뢰도 알약형 표시 | `bg_dismiss_pill.xml` |
| 하단 패널 | 상단 둥근 모서리 + 그립 인디케이터 + 타이포 정리 | `bg_dismiss_panel.xml` |

- 추가 토큰: `colors.xml`(반투명 6종), `dimens.xml`(`radius_lg/pill`, 조준틀·스크림 크기), `strings.xml`(안내 문구 2종).
- minSdk 24 호환을 위해 `paddingHorizontal/Vertical`(API26) 대신 `paddingStart/End/Top/Bottom` 사용.

**변경 파일**: `res/layout/activity_dismiss.xml`, `res/drawable/bg_dismiss_*.xml`, `res/values/{colors,dimens,strings}.xml`

## 5. 로그인 / 회원가입 구현

### 5.1 진단 — "백엔드만 있고 프론트가 비어있던" 페이지

| 항목 | 작업 전 상태 |
|---|---|
| `UserEntity`(email unique, password_hash/salt) | ✅ 스키마만 존재 |
| 인증 repository / 해시 / 세션 | ❌ 없음 (BE 문서상 Phase B4 미구현) |
| `LoginActivity` | ⚠️ 스텁 — 형식 검증 후 통과, 비밀번호 없음, DB 인증 안 함 |
| 회원가입 화면 | ❌ 없음 (`signupButton`은 클릭해도 무동작) |

→ 인증은 사실상 양쪽 다 미완성이라, repository 경계를 지키며 **end-to-end로 신규 구현**했다.

### 5.2 백엔드 (인증 계층)

```text
model/AuthResult.java                 // SUCCESS / INVALID_CREDENTIALS / EMAIL_TAKEN / ERROR
repository/AuthRepository.java        // login / register 경계
repository/room/RoomAuthRepository.java
util/PasswordHasher.java              // PBKDF2 + per-user salt
data/dao/UserDao.java                 // getByEmail / insertNew 추가
repository/Repositories.java          // auth() 추가
```

- **비밀번호 해시**: `PBKDF2WithHmacSHA1`(minSdk 24 호환 — SHA256 변형은 API 26+), per-user salt, 120k iterations, Base64 보관. 평문은 저장하지 않으며 검증은 상수시간 비교.
- **회원가입**: 이메일 정규화(트림·소문자) → `getByEmail` 중복 검사 → 신규 계정은 `exp=0 / 레벨1 / 하급닌자`(성장표와 일관)로 생성. unique 충돌은 `EMAIL_TAKEN`으로 처리(`insertNew`는 ABORT라 기존 계정을 덮지 않음).
- **로그인**: 이메일로 조회 → 해시 검증. 비밀번호 없는 시드 게스트 계정은 비번 로그인 불가.

### 5.3 세션

```text
util/Session.java   // 현재 user_id 를 SharedPreferences 에 보관
```

- 명시적 세션이 없으면 `GUEST_USER_ID=1`(시드 게스트)로 동작.
- 화면/리포지토리가 하드코딩 id 대신 `Session.userId(ctx)`를 사용하도록 통일:
  `ProfileFragment`, `StatsActivity`, `TutorialActivity`, `RoomDismissRepository`.
- `Repositories.CURRENT_USER_ID`는 `@Deprecated` 처리(= `Session.GUEST_USER_ID` 호환값).

### 5.4 프론트 페이지

- `LoginActivity` — 이메일+비밀번호 실인증(해시 검증은 백그라운드 스레드), 가입/게스트 버튼 연결.
- `RegisterActivity`(신규) — 이메일·닉네임·비번·비번확인 검증 → 가입 성공 시 자동 로그인 후 홈.
- `activity_login.xml` 리디자인(비밀번호 토글·로고·게스트), `activity_register.xml` 신규.
- `SplashActivity` — 세션 있으면 홈, 없으면 로그인으로 라우팅.
- `AndroidManifest.xml`에 `RegisterActivity` 등록, `strings.xml`에 인증 문구 추가.

### 5.5 흐름

```text
Splash → (세션 없음) Login
   ├─ 회원가입 → PBKDF2 저장 → 자동 로그인 → Home
   ├─ 로그인   → 해시 검증   → 세션 저장   → Home
   └─ 게스트   → 시드 게스트(id=1)         → Home
```
