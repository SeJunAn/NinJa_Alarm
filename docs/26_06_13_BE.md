## 1. 작업 목적

기존 앱은 알람 정보를 Room DB에 저장하고 해제 화면을 체험할 수 있었지만, Android OS에 실제 알람을 예약하지는 않았다.

이번 작업의 목적은 저장된 알람을 Android `AlarmManager`와 연결하여 다음 흐름을 동작하게 만드는 것이다.

```text
알람 저장/수정/ON/OFF/삭제
  -> AlarmManager 예약/취소
  -> 지정 시간 도달
  -> AlarmReceiver 수신
  -> AlarmService 알람음/진동/알림 시작
  -> DismissActivity에서 인식 성공
  -> ACTION_STOP_ALARM 브로드캐스트
  -> AlarmService 정지
```

---

## 2. 적용한 주요 변경 사항

### 2.1 AlarmScheduler 추가

`app/src/main/java/com/ninja/alarm/alarm/AlarmScheduler.java`를 추가하였다.

역할은 다음과 같다.

- `AlarmManager.setAlarmClock()`으로 실제 OS 알람 예약
- 알람별 `PendingIntent` 생성
- 알람 삭제/OFF 시 예약 취소
- 부팅 후 enabled 알람 일괄 재예약
- 반복 요일 bitmask 기반 다음 울림 시각 계산

반복 요일 bitmask는 기존 모델과 동일하게 사용한다.

```text
bit0 = 월
bit1 = 화
bit2 = 수
bit3 = 목
bit4 = 금
bit5 = 토
bit6 = 일
0    = 단발 알람
```

---

## 3. AlarmReceiver 추가

`app/src/main/java/com/ninja/alarm/alarm/AlarmReceiver.java`를 추가하였다.

역할은 다음과 같다.

- `AlarmScheduler.ACTION_FIRE_ALARM` 수신 시 DB에서 알람 조회
- 알람이 아직 enabled 상태이면 `AlarmService` 시작
- 반복 알람은 다음 회차 재예약
- 단발 알람은 울린 뒤 DB에서 OFF 처리
- `BOOT_COMPLETED` 수신 시 enabled 알람 재예약

---

## 4. AlarmService 추가

`app/src/main/java/com/ninja/alarm/alarm/AlarmService.java`를 추가하였다.

역할은 다음과 같다.

- Foreground service로 알람 실행
- 기본 알람음 반복 재생
- 진동 패턴 반복 실행
- 알림 및 full-screen intent로 `DismissActivity` 진입 제공
- `RoomDismissRepository.ACTION_STOP_ALARM` 브로드캐스트 수신 시 알람음/진동/알림 정지

해제 성공 시 기존 코드가 이미 아래 브로드캐스트를 보내고 있었으므로, 서비스에서 이를 받아 정지하도록 연결하였다.

```java
RoomDismissRepository.ACTION_STOP_ALARM
```

---

## 5. RoomAlarmRepository 연동

`RoomAlarmRepository`에 `AlarmScheduler`를 연결하였다.

| 동작 | 처리 |
|---|---|
| 알람 신규 저장 | DB insert 후 enabled이면 schedule |
| 알람 수정 | 기존 예약 cancel 후 DB update, enabled이면 schedule |
| 알람 ON | DB enabled=1 후 schedule |
| 알람 OFF | DB enabled=0 후 cancel |
| 알람 삭제 | cancel 후 DB delete |

이제 UI는 기존처럼 `Repositories.alarm().upsert(...)`, `setEnabled(...)`, `delete(...)`만 호출하면 되고, 실제 OS 예약은 Repository 내부에서 같이 처리된다.

---

## 6. 신규 알람 ID 보정

`RoomMappers.toEntity(...)`에서 새 알람의 id를 보정하였다.

기존 UI는 새 알람을 만들 때 `alarmId = -1`을 사용한다. Room의 `@PrimaryKey(autoGenerate = true)`는 id가 `0`일 때 자동 생성되므로, `-1`이 그대로 들어가면 자동 증가가 정상적으로 동작하지 않을 수 있다.

따라서 다음처럼 수정하였다.

```java
alarm.alarmId > 0 ? alarm.alarmId : 0
```

## 7. Manifest / 권한 추가

`AndroidManifest.xml`에 실제 알람 발화에 필요한 권한과 컴포넌트를 추가하였다.

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
<uses-permission android:name="android.permission.USE_EXACT_ALARM" />
<uses-permission android:name="android.permission.USE_FULL_SCREEN_INTENT" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<uses-permission android:name="android.permission.VIBRATE" />
```

등록한 컴포넌트:

```xml
<receiver android:name=".alarm.AlarmReceiver" ... />
<service android:name=".alarm.AlarmService" ... />
```

## 8. 알림 권한 요청

Android 13(API 33)+에서는 알림 표시를 위해 `POST_NOTIFICATIONS` 런타임 권한이 필요하다.

`HomeActivity`에서 앱 진입 시 권한이 없으면 한 번 요청하도록 추가하였다.

알람 서비스는 권한이 없어도 시작될 수 있지만, 사용자가 알람 상태를 명확히 보고 해제 화면으로 들어가기 위해 알림 권한을 받는 쪽이 안전하다.

## 11. 수동 테스트 체크리스트

실기기 또는 에뮬레이터에서 다음 순서로 확인한다.

1. 앱 실행 후 알림 권한 허용
2. 현재 시간보다 1~2분 뒤로 알람 생성
3. 앱을 백그라운드로 이동
4. 지정 시간이 되면 알림/알람음/진동이 시작되는지 확인
5. 알림 또는 full-screen intent로 해제 화면 진입 확인
6. 인식 성공 시 알람음/진동이 멈추는지 확인
7. 반복 알람은 다음 회차가 재예약되는지 확인
8. 단발 알람은 울린 뒤 OFF 처리되는지 확인
9. 기기 재부팅 후 enabled 알람이 다시 예약되는지 확인

## 13. 요약

이번 작업으로 Room에 저장된 알람이 실제 Android OS 알람 예약과 연결되었다. 알람 저장/수정/토글/삭제는 `RoomAlarmRepository`를 통해 자동으로 예약 상태를 반영하며, 알람 시간이 되면 `AlarmReceiver -> AlarmService -> DismissActivity` 흐름으로 알람음/진동과 해제 화면을 제공한다.
