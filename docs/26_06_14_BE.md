## 1. 작업 배경

실기기 테스트 결과 실제 알람 발화는 정상 동작했으나, 다음 문제가 확인되었다.

```text
1. 앱 실행 후 알림 권한 허용                         O
2. 현재 시간보다 1~2분 뒤로 알람 생성               O
3. 앱을 백그라운드로 이동                           O
4. 지정 시간이 되면 알림/알람음/진동 시작           O
5. 알람 울림과 동시에 해제 화면 진입                X
   - 상단바 알림을 눌러야 해제 화면 진입 가능
6. 인식 성공 시 알람음/진동 정지                    X
7. 반복 알람 다음 회차 재예약                       추후 확인
8. 단발 알람 울림 후 OFF 처리                       추후 확인
9. 기기 재부팅 후 enabled 알람 재예약               추후 확인
추가. 알람음 변경                                  X
```

이번 작업은 우선순위에 따라 아래 3가지를 수정하였다.

1. 인식 성공 후 알람음/진동 정지 안정화
2. 알람 울림 시 해제 화면 자동 진입 보강
3. 알람음 선택 기능 구현

## 2. 인식 성공 후 알람 정지 안정화

### 2.1 기존 구조

기존에는 `DismissActivity`가 해제 성공을 기록하면 `RoomDismissRepository`에서 다음과 같이 implicit broadcast를 보냈다.

```java
appContext.sendBroadcast(new Intent(ACTION_STOP_ALARM));
```

그리고 `AlarmService`는 동적으로 등록한 `BroadcastReceiver`가 이 action을 받으면 `stopAlarm()`을 호출하는 구조였다.

### 2.2 문제

구조상 동작할 수는 있지만, 실제 기기에서 해제 성공 후에도 알람음/진동이 멈추지 않는 문제가 있었다.

원인은 다음 가능성이 크다.

- action만 있는 implicit broadcast라 전달 경로가 약함
- `AlarmService`의 동적 receiver가 서비스 생명주기나 OS 정책에 따라 안정적으로 받지 못할 수 있음
- 정지 요청이 서비스 자체의 명시적 명령으로 들어가지 않음

### 2.3 수정

`RoomDismissRepository`에서 `AlarmService`를 명시적으로 지정해 `ACTION_STOP_ALARM` intent를 보낸다.

```java
Intent stop = new Intent(appContext, AlarmService.class)
        .setAction(ACTION_STOP_ALARM);
appContext.startService(stop);
```

`AlarmService.onStartCommand()`에서는 `ACTION_STOP_ALARM`을 직접 처리한다.

```java
if (intent != null && RoomDismissRepository.ACTION_STOP_ALARM.equals(intent.getAction())) {
    stopAlarm();
    return START_NOT_STICKY;
}
```

이제 해제 성공 시 정지 요청이 `AlarmService`로 직접 들어가므로 알람음/진동 정지 경로가 더 명확해졌다.

## 3. 알람 울림 시 해제 화면 자동 진입 보강

### 3.1 기존 구조

기존 `AlarmService`는 알림에 full-screen intent와 content intent를 설정했다.

```java
.setContentIntent(dismissIntent)
.setFullScreenIntent(dismissIntent, true)
```

하지만 Android 버전, 잠금화면 상태, 제조사 정책, full-screen intent 허용 여부에 따라 실제로는 상단바 알림만 표시될 수 있다.

### 3.2 수정

알람 시작 시 `AlarmService`가 `DismissActivity`를 직접 실행하도록 보강하였다.

```java
private void openDismissScreen(long alarmId) {
    try {
        startActivity(dismissIntent(alarmId));
    } catch (Exception ignored) {
        // Full-screen notification remains as fallback if background launch is restricted.
    }
}
```

`onStartCommand(ACTION_START_ALARM)` 흐름:

```text
startForeground(notification)
-> startSound()
-> startVibration()
-> openDismissScreen(alarmId)
```

기존 full-screen notification은 fallback으로 유지한다.

### 3.3 DismissActivity 잠금화면 보강

`AndroidManifest.xml`에서 `DismissActivity`에 다음 속성을 추가하였다.

```xml
android:showWhenLocked="true"
android:turnScreenOn="true"
```

화면이 꺼져 있거나 잠금화면 상태일 때 해제 화면 노출 가능성을 높이기 위한 설정이다.

## 4. 알람음 선택 기능 구현

### 4.1 기존 상태

알람 추가 화면과 설정 화면에는 `알람음 / 기본 알람음` 텍스트가 있었지만 실제 동작은 없었다.

`activity_add_alarm.xml`에도 아래처럼 정적 UI로만 존재했다.

```xml
<!-- 알람음(정적) -->
```

또한 `AlarmService`는 항상 시스템 기본 알람음을 사용했다.

```java
RingtoneManager.getDefaultUri(RingtoneManager.TYPE_ALARM)
```

### 4.2 저장 방식

DB 마이그레이션 없이 전역 앱 설정으로 처리하기 위해 `AppPrefs`에 알람음 URI와 표시 이름을 저장하도록 추가하였다.

```java
KEY_ALARM_SOUND_URI
KEY_ALARM_SOUND_TITLE
```

추가 API:

```java
getAlarmSoundUri(Context)
getAlarmSoundTitle(Context)
setAlarmSound(Context, String uri, String title)
```

### 4.3 알람 추가/편집 화면

`activity_add_alarm.xml`의 알람음 행에 id와 클릭 상태를 추가하였다.

```xml
android:id="@+id/soundRow"
android:clickable="true"
android:focusable="true"
```

표시 텍스트에는 `soundValue` id를 추가하였다.

`AddAlarmActivity`에서는 `RingtoneManager.ACTION_RINGTONE_PICKER`를 실행하고, 선택한 URI와 제목을 `AppPrefs`에 저장한다.

```java
AppPrefs.setAlarmSound(this, uri.toString(), titleFor(uri));
```

### 4.4 설정 화면

`SettingsActivity`의 알람음 행(`rowSound`)도 같은 ringtone picker를 열도록 연결하였다.

설정 화면과 알람 추가 화면은 같은 `AppPrefs` 값을 바라본다.

### 4.5 알람 재생

`AlarmService`는 먼저 저장된 알람음 URI를 확인한다.

```java
String saved = AppPrefs.getAlarmSoundUri(this);
```

저장된 URI가 있으면 해당 알람음을 재생하고, 실패하면 기본 알람음으로 fallback한다.

```text
저장된 알람음 URI
  -> 실패 시 TYPE_ALARM 기본음
  -> 없으면 TYPE_NOTIFICATION fallback
```

## 7. 재테스트 체크리스트

이번 수정 후 우선 확인할 항목은 다음과 같다.

```text
1. 알람 시간 도달 시 해제 화면이 자동으로 뜨는지
2. 자동 진입이 OS 정책으로 막힐 때 기존 알림 탭 진입이 유지되는지
3. 인식 성공 시 알람음이 멈추는지
4. 인식 성공 시 진동이 멈추는지
5. 알람 추가 화면의 알람음 행 클릭 시 picker가 뜨는지
6. 설정 화면의 알람음 행 클릭 시 picker가 뜨는지
7. 선택한 알람음 이름이 화면에 표시되는지
8. 선택한 알람음으로 실제 알람이 울리는지
9. 반복 알람 다음 회차 재예약 확인
10. 단발 알람 울림 후 OFF 처리 확인
11. 기기 재부팅 후 enabled 알람 재예약 확인
```

## 8. 남은 주의사항

```text
Android 최신 버전에서는 백그라운드 activity launch가 제한될 수 있음.
따라서 직접 startActivity가 막혀도 full-screen notification/content intent fallback은 유지해야 한다.

알람음 선택은 현재 전역 설정 방식이다.
알람별 개별 알람음을 지원하려면 AlarmEntity 스키마 확장과 Room migration이 필요하다.
```

---

## 9. 요약

이번 작업으로 해제 성공 후 알람 정지 경로를 `AlarmService` 직접 명령 방식으로 안정화했고, 알람 울림 시 해제 화면 자동 진입을 보강했다. 또한 기존 정적 UI였던 알람음 행을 실제 ringtone picker와 연결하여 전역 알람음 선택 기능을 추가하였다.
